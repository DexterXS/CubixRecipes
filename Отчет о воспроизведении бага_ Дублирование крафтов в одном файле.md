# Отчет о воспроизведении бага: Дублирование крафтов в одном файле

## 1. Описание бага
При попытке изменить и сохранить существующий крафт в облако, вместо перезаписи старого блока кода в `.zs` файле создается новый блок, дублирующий рецепт. После перезагрузки страницы, система продолжает отображать старую версию крафта, создавая иллюзию, что изменения не были сохранены.

## 2. Цель тестирования
Подтвердить, что:
1. Метод `save_as` на бэкенде всегда дописывает новый рецепт в файл, даже если он уже существует.
2. Механизм поиска рецептов возвращает все найденные блоки, а фронтенд выбирает первый, что приводит к отображению устаревшей версии.

## 3. Сценарий тестирования
Был разработан Python-скрипт `reproduce_bug.py`, который имитирует последовательность действий пользователя:
1. **Инициализация:** Создается временная директория и экземпляр `ZsStorage`.
2. **Первое сохранение:** Создается новый рецепт для `<minecraft:stone>` и сохраняется в `test_recipe.zs` с использованием `storage.save_as`. Это имитирует первое сохранение крафта в облако.
3. **Второе сохранение (изменение):** Рецепт модифицируется (добавляется `<minecraft:dirt>` в матрицу), и снова вызывается `storage.save_as` в тот же `test_recipe.zs`. Это имитирует попытку пользователя обновить уже существующий крафт через UI, который ошибочно вызывает `save_as`.
4. **Проверка файла:** Содержимое `test_recipe.zs` считывается для подтверждения наличия двух блоков рецептов.
5. **Имитация поиска:** Вызывается `storage.scan()` для обновления индекса, затем `storage.search_by_output()` для поиска рецептов, связанных с `<minecraft:stone>`. Проверяется, какой рецепт будет выбран фронтендом (`matches[0]`).

## 4. Скрипт воспроизведения (`reproduce_bug.py`)

```python
import sys
import os
from pathlib import Path

# Добавляем путь к бэкенду, чтобы импортировать модули
sys.path.append("/home/ubuntu/CubixRecipes/backend")

from app.storage.zs_storage import ZsStorage
from app.services.recipe_service import RecipeService
from app.parsers.recipe_parser import RecipeParser

def run_test():
    print("--- ЗАПУСК ТЕСТА ВОСПРОИЗВЕДЕНИЯ БАГА ---")
    
    # 1. Настройка временного окружения
    test_dir = Path("/home/ubuntu/test_scripts")
    test_dir.mkdir(exist_ok=True)
    scripts_dir = test_dir / "scripts"
    scripts_dir.mkdir(exist_ok=True)
    
    storage = ZsStorage(scripts_dir)
    parser = RecipeParser()
    service = RecipeService(storage, parser)
    
    recipe_file = "test_recipe.zs"
    output_item = "<minecraft:stone>"
    
    print(f"Целевой файл: {recipe_file}")
    print(f"Предмет: {output_item}")
    
    # 2. Первое сохранение (имитация 'Сохранить как')...
    print("\n1. Первое сохранение (имитация 'Сохранить как')...")
    initial_recipe = service.create_recipe("ct_shaped", output_item)
    rendered_v1 = service.render_recipe(initial_recipe)
    uid_v1 = storage.save_as(rendered_v1, recipe_file)
    print(f"Результат: Сохранено с UID: {uid_v1}")
    
    # 3. Второе сохранение того же крафта (имитация повторного 'Сохранить как' или бага UI)
    print("\n2. Второе сохранение (измененный рецепт, имитация повторного 'Сохранить как')...")
    # Изменим матрицу, чтобы рецепт отличался
    modified_matrix = [[None for _ in range(3)] for _ in range(3)]
    modified_matrix[0][0] = "<minecraft:dirt>"
    
    # Получаем текущий рецепт из хранилища
    current_recipe = storage.get_recipe(uid_v1)
    updated_recipe = service.update_recipe(current_recipe, output_item, modified_matrix, "Modified Stone")
    rendered_v2 = service.render_recipe(updated_recipe)
    
    # Снова вызываем save_as (как делает фронтенд при нажатии 'Сохранить в облако' для новых/несинхронизированных рецептов)
    uid_v2 = storage.save_as(rendered_v2, recipe_file)
    print(f"Результат: Сохранено с UID: {uid_v2}")
    
    # 4. Проверка содержимого файла
    full_path = scripts_dir / recipe_file
    content = full_path.read_text()
    print("\n--- СОДЕРЖИМОЕ ФАЙЛА ---")
    print(content)
    print("------------------------")
    
    blocks_count = content.count("recipes.addShaped")
    print(f"Количество блоков рецептов в файле: {blocks_count}")
    
    # 5. Имитация поиска рецепта (как делает фронтенд после перезагрузки)
    print("\n3. Имитация поиска рецепта после перезагрузки страницы...")
    storage.scan() # Пересканируем, чтобы обновить индекс
    matches = storage.search_by_output(output_item)
    
    print(f"Найдено совпадений в индексе: {len(matches)}")
    for i, m in enumerate(matches):
        print(f"  [{i}] UID: {m.recipe_uid}, Имя: {m.name}, Путь: {m.source.path}, Смещение: {m.source.start_offset}")
    
    print(f"\nИТОГ: Фронтенд выберет matches[0], то есть UID: {matches[0].recipe_uid}")
    if matches[0].recipe_uid == uid_v1:
        print("!!! ПОДТВЕРЖДЕНО: Выбран СТАРЫЙ рецепт, хотя новый был добавлен в тот же файл.")
    else:
        print("Выбран новый рецепт (поведение отличается от ожидаемого бага).")

if __name__ == "__main__":
    run_test()
```

## 6. Выводы
Тест однозначно подтверждает, что:
1. Метод `storage.save_as` (который используется при первом сохранении в облако или при повторном вызове `handleSaveAs` на фронтенде) **дописывает новый блок рецепта в конец файла**, не удаляя и не заменяя старый.
2. После пересканирования, `storage.search_by_output` находит оба блока рецепта.
3. Фронтенд, выбирая `matches[0]`, всегда будет отображать первый найденный рецепт, который в данном случае является старой версией, расположенной в начале файла.

Это объясняет, почему пользователь видит старый рецепт после сохранения и перезагрузки, несмотря на то, что новая версия была добавлена в тот же файл.

## 7. Рекомендации по исправлению

### 7.1. Краткосрочное решение (для пользователя)
* **Ручная очистка:** Открывать `.zs` файлы в текстовом редакторе и вручную удалять дублирующиеся блоки рецептов, оставляя только самую актуальную версию.
* **Осторожное использование "Сохранить в облако":** Избегать повторного использования этой функции для уже сохраненных рецептов, если не требуется именно создание новой версии.

### 7.2. Долгосрочное решение (для разработчика)
1.  **Изменение логики `save_as` на бэкенде:** Метод `save_as` (`backend/app/storage/zs_storage.py`) должен быть модифицирован для определения, существует ли уже рецепт с таким же `output_item` в целевом файле. Если да, то вместо дозаписи он должен либо:
    *   **Заменять** существующий блок (по аналогии с `save_existing`).
    *   **Предлагать пользователю выбор** (заменить или создать новый).
2.  **Улучшение фронтенда:**
    *   При обнаружении нескольких рецептов с одинаковым `output_item` в одном файле, UI должен явно уведомлять пользователя о дубликатах и предоставлять удобный интерфейс для их разрешения (например, удаление старых версий или выбор, какую версию отображать по умолчанию).
    *   Пересмотреть логику `handleSaveToCloud` (`frontend/src/pages/App.tsx`), чтобы после первого сохранения в облако, последующие нажатия на "Сохранить в облако" для того же рецепта вызывали `handleSave` (который использует `save_existing` для перезаписи блока), а не `handleSaveAs` (который дописывает).
