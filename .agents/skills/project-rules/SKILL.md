# project-rules

## When to use
- Use this skill when changing `AGENTS.md`, project memory, roadmap status, or `.agents/skills`.

## Steps
1. Read `AGENTS.md` first.
2. Check `.agents/skills` for empty, duplicate, stale, or overly broad instructions.
3. Keep durable rules in `AGENTS.md`; keep repeatable workflows in skills.
4. Do not encode one-off task details as permanent rules.
5. Update roadmap status when architecture or optimization stages move.

## Common mistakes
- Adding rules that conflict with cautious default mode.
- Creating placeholder skills.
- Duplicating the same checklist in every skill.
- Forgetting to preserve the modular-monolith goal.

## Done criteria
- Agent instructions are consistent.
- Skills are actionable and scoped.
- The next agent can continue without re-discovering the current plan.
